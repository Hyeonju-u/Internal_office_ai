# 사내 규정 AI (Local RAG)

외부 AI를 쓸 수 없는 보안 환경을 가정하고 만든 사내 문서 기반 질의응답 시스템입니다. 모든 처리가 내부 서버(로컬)에서 이루어지므로 문서와 질문이 외부로 나가지 않습니다. 로그인한 직원의 부서에 따라 볼 수 있는 문서만 검색됩니다.

## 만든 이유

많은 회사가 보안 문제로 ChatGPT 같은 외부 AI에 사내 파일을 올리지 못하게 합니다. 그래서 직원들은 AI로 업무를 줄일 수 있는데도 쓰지 못합니다.

이 프로젝트는 다음 세 가지로 대응합니다.

- 외부 API 대신 로컬 LLM(Ollama)을 써서 데이터가 서버 밖으로 나가지 않습니다.
- 문서를 AI에게 통째로 주지 않고, 질문과 관련된 조항만 검색해서 전달합니다 (RAG).
- 권한 필터를 AI 앞단인 검색 단계에 두어, AI가 볼 수 없는 문서는 답변에도 나오지 않습니다.

## 동작 흐름

```
① 직원이 브라우저에서 로그인 후 질문 입력
        ↓
② 서버가 세션으로 신원·부서 확인          (Flask session, 비밀번호 해시 검증)
        ↓
③ 내 부서가 볼 수 있는 문서만 DB에서 조회   (SQLite, SQL WHERE)
        ↓
   질문을 임베딩 → 조항들과 코사인 유사도 비교 → 1등 조항 선택
        ↓
④ 점수 기준 미달이면 AI 호출 없이 "찾을 수 없습니다"
   통과하면 해당 조항 1개만 LLM에 전달해 근거 조항과 함께 답변 생성
        ↓
⑤ 답변 표시 + 질문 로그 저장               (누가/언제/무엇을/어떤 문서로/몇 점)
```

## 기술 스택

| 구분 | 사용 기술 |
|---|---|
| 답변 생성 LLM | Ollama + `qwen2.5:7b` (로컬 실행) |
| 임베딩 모델 | Ollama + `bge-m3` (다국어, 한국어 지원) |
| 유사도 검색 | 코사인 유사도 (직접 구현) |
| 저장소 | SQLite (`rules.db`: docs / users / logs) |
| 웹 / 인증 | Flask, Flask session, Werkzeug 비밀번호 해시 |
| 개발 환경 | MacBook Air M4 16GB, Python 3, venv |

## 파일 구조

```
local-ai/
├── 규정.txt           # 원본 규정 문서 ([제목 | 공개범위] 형식)
├── build_db.py        # 규정 → 조항 단위 분할 → 임베딩 → DB 저장 (규정 변경 시에만 실행)
├── create_users.py    # 테스트 직원 계정 생성 (비밀번호는 해시로 저장)
├── create_logs.py     # 질문 로그 테이블 생성
├── ask.py             # 핵심 로직: answer(부서, 질문) → (답변, 근거 문서, 점수)
├── app.py             # Flask 웹 서버 (로그인, 질문 화면, 로그 기록)
├── rules.db           # SQLite DB
└── practice/          # 단계별 학습용 코드
```

### 규정 문서 형식

```
[제15조 출장비 | 전체]
1. 국내 출장 숙박비는 1박 10만원 한도로 실비 지급한다.
...

[제20조 임원보수 | 인사팀]
1. 임원 보수는 매년 3월 이사회에서 결정한다.
...
```

`|` 뒤가 공개 범위입니다. `전체`는 모든 직원, 부서명이면 해당 부서만 검색됩니다.

## 실행 방법

```bash
# 1. 모델 준비
ollama pull qwen2.5:7b
ollama pull bge-m3
brew services start ollama

# 2. 가상환경
python3 -m venv .venv
source .venv/bin/activate
pip install flask

# 3. DB 준비
python3 build_db.py
python3 create_users.py
python3 create_logs.py

# 4. 서버 실행
python3 app.py
# → http://127.0.0.1:5000
```

## 보안 설계

### 1. 권한 필터는 검색 단계에 둔다
AI에게 모든 문서를 주고 "인사팀 문서는 말하지 마"라고 지시하면, 모델이 실수하거나 프롬프트 조작에 속을 수 있습니다. 그래서 SQL 조회 단계에서 권한 없는 문서를 아예 꺼내지 않습니다. AI는 받지 못한 정보를 말할 수 없습니다.

```sql
SELECT title, text, embedding FROM docs WHERE dept = '전체' OR dept = ?
```

### 2. 부서 정보는 서버가 결정한다
초기 버전은 화면 드롭다운에서 부서를 고르게 했습니다. 이 방식에서는 누구나 "인사팀"을 골라 권한을 우회할 수 있었습니다. 지금은 로그인 시 서버가 DB에서 확인한 부서만 세션에 저장하고, 질문 처리에는 세션 값만 사용합니다.

### 3. 비밀번호는 솔트가 포함된 해시로 저장
원문 비밀번호는 저장하지 않습니다. 사용자마다 솔트가 달라서 같은 비밀번호라도 해시 값이 모두 다릅니다.

### 4. 로그인 실패 메시지 통일
아이디가 없는 경우와 비밀번호가 틀린 경우를 같은 메시지로 처리해, 계정이 존재하는지 알 수 없게 했습니다.

### 5. 다층 검증
- 1차: 유사도 점수 기준(0.55) 미달 시 LLM 호출 없이 거절
- 2차: 프롬프트로 "규정에 없는 내용이면 찾을 수 없다고 답하라" 지시
- 1차를 간신히 통과한 무관한 조항(0.505)을 2차에서 막은 적이 있습니다.

### 6. 감사 로그
질문마다 시간, 사용자, 부서, 질문, 답변, 근거 문서, 점수를 기록합니다.

```
2026-11-02 17:38:38|kim|임원 보수 언제 나와?|제12조 연차휴가|0.495   ← 영업팀: 임원보수 검색 대상 아님 → 거절
2026-11-02 17:40:25|lee|임원 보수 언제 나와?|제20조 임원보수|0.690   ← 인사팀: 정상 답변
2026-11-02 17:40:41|lee|법카 한도는?|제12조 연차휴가|0.393         ← 규정에 없음 → 추가할 규정 후보
```

## 트러블슈팅 기록

| 문제 | 원인 | 해결 |
|---|---|---|
| 규정 없이 질문하면 "연차 10일"처럼 틀린 답을 자신 있게 함 | LLM이 학습 데이터 기반으로 그럴듯한 답을 생성 (할루시네이션) | 관련 조항을 프롬프트에 함께 전달 (RAG) |
| 애매한 질문에 답변 중간부터 중국어로 바뀜 | 작은 모델이 불확실할 때 주 학습 언어로 회귀 | 프롬프트에 언어 지시 강화, `temperature: 0` |
| "정산 안 하면?" 질문에 "처벌 없음으로 간주"라고 단정 | 규정에 없는 내용을 모델이 추론으로 채움 | 근거 기반 답변 지시 + 점수 기준 검증 |
| 같은 질문인데 실행할 때마다 답이 다름 | 생성 랜덤성 | `temperature: 0` |
| "호텔비" 질문을 키워드 검색으로 못 찾음 | 규정에는 "숙박비"로만 표기 | 임베딩 기반 의미 검색 도입 → "호텔"이 없어도 출장비 조항 0.632로 1위 |
| 규정에 없는 질문에도 무조건 1등 조항을 AI에 전달 | 최고점만 고르고 최소 기준이 없음 | 유사도 기준값 도입 |
| 기준 0.5에서 무관한 조항이 0.505로 통과 | 기준이 무관 질문 점수(0.47~0.50)와 너무 가까움 | 기준 0.55로 조정 (추후 평가셋으로 재조정 예정) |
| 실행할 때마다 모든 조항을 다시 임베딩해 느림 | 매 요청마다 문서 임베딩 재계산 | 임베딩을 DB에 미리 저장, 질문만 임베딩 |
| 빈 질문 전송 시 서버 에러 (IndexError) | 빈 문자열 임베딩 결과가 빈 목록 | 서버 측 입력 검증 + HTML `required` |
| 개발용 에러 화면에 코드 경로·실행 콘솔 노출 | Flask `debug=True` | 배포 시 `debug=False` 필수 |
| 함수 안에서 `exit()` 사용 시 서버 전체 종료 위험 | 웹 서버에서 `exit()`는 프로세스를 종료 | `return`으로 변경 |

## 한계와 다음 계획

### 현재 한계
- 조항 단위 청킹이라 한 조항 안의 여러 항목(숙박비/식비/정산)이 구분되지 않음
- 테스트 문서가 3개 조항뿐이라 기준 점수가 충분히 검증되지 않음
- 권한 때문에 막힌 질문과 규정에 없는 질문이 로그에서 구분되지 않음
- SQLite는 동시 쓰기가 많은 대규모 환경에 부적합
- DB 파일 자체가 유출되면 권한과 무관하게 모든 문서가 노출됨
