# 사내 규정 AI (Local RAG)

외부 AI를 쓸 수 없는 보안 환경을 가정하고 만든 **사내 문서 기반 질의응답 시스템**입니다.
모든 처리가 내부 서버(로컬)에서 이루어져 문서와 질문이 외부로 나가지 않으며,
로그인한 직원의 부서에 따라 **볼 수 있는 문서만 검색**되도록 설계했습니다.

- 문서: 근로기준법 132개 조항 + 가상 사내 규정 3개 조항 (부서별 공개 범위 포함)
- 평가: 30문항 평가셋으로 검색 방식과 기준값을 비교해 결정

---

## 만든 이유

많은 회사가 보안 문제로 ChatGPT 같은 외부 AI에 사내 파일을 올리는 것을 막고 있습니다.
그 결과 직원들은 AI로 업무를 줄일 수 있는데도 쓰지 못합니다.

이 프로젝트는 그 문제를 이렇게 풉니다.

- 외부 API 대신 **로컬 LLM(Ollama)** 사용 → 데이터가 서버 밖으로 나가지 않음
- 문서를 AI에게 통째로 주지 않고 **질문과 관련된 조항만 검색해서** 전달 (RAG)
- **권한 필터를 AI 앞단(검색 단계)에 배치** → AI는 볼 수 없는 문서를 말할 수 없음
- **모르면 모른다고 답하도록** 검색 점수 기준과 출력 검증을 둠

---

## 동작 흐름

```
① 직원이 브라우저에서 로그인 후 질문 입력
        ↓
② 서버가 세션으로 신원·부서 확인              (Flask session, 비밀번호 해시 검증)
        ↓
③ 권한 있는 조항만 대상으로 하이브리드 검색     (임베딩 유사도 + 키워드 보너스)
        ↓
④ 1등 점수가 기준(0.60) 미만이면 AI 호출 없이 "찾을 수 없습니다"
   통과하면 1등과 점수 차이 0.1 이내 조항(최대 3개)만 LLM에 전달
        ↓
⑤ 답변 생성 → 출력 검증(중국어 섞이면 재생성)
        ↓
⑥ 답변 표시 + 질문 로그 저장                  (누가/언제/무엇을/어떤 문서로/몇 점)
```

## 기술 스택

| 구분 | 사용 기술 |
|---|---|
| 답변 생성 LLM | Ollama + `qwen2.5:7b` (로컬 실행) |
| 임베딩 모델 | Ollama + `bge-m3` (다국어, 한국어 지원) |
| 검색 | 코사인 유사도 + 2글자 n-gram IDF 키워드 점수 (직접 구현) |
| 문서 처리 | pypdf, 정규표현식 기반 조항 분할 |
| 저장소 | SQLite (`rules.db`: docs / users / logs) |
| 웹 / 인증 | Flask, Flask session, Werkzeug 비밀번호 해시 |
| 개발 환경 | MacBook Air M4 16GB, Python 3, venv |

```

├── build_db.py         # 사내 규정 + 근로기준법 → 조항 분할 → 임베딩 → DB 저장
├── create_users.py     # 테스트 직원 계정 생성 (비밀번호는 해시로 저장)
├── create_logs.py      # 질문 로그 테이블 생성
├── ask.py              # 핵심 로직: answer(부서, 질문) → (답변, 근거 문서, 점수)
├── app.py              # Flask 웹 서버 (로그인, 질문 화면, 로그 기록)
├── eval_set.json       # 평가셋 30문항 (질문, 부서, 정답 조항)
├── eval.py             # 임베딩 검색 평가 (기준값별 비교)
├── eval_hybrid.py      # 하이브리드 검색 평가 (보너스 비중 × 기준값 비교)
└── practice/           # 단계별 학습용 코드
```

## 문서 처리

### 사내 규정
`[제20조 임원보수 | 인사팀]`처럼 제목 옆에 공개 범위를 적고, `[`와 `|` 기준으로 분할합니다.

### 근로기준법 (PDF)
- **조항 시작 인식**: 정규표현식 `제(\d+)조(의\d+)?\(`
  본문 속 "제17조에 따라" 같은 언급은 바로 뒤에 `(`가 없어 제외됩니다.
- **부칙 제거**: 조항 번호가 이전보다 **작아지는 지점**(제116조 → 제1조)을 부칙 시작으로 판단하고,
  그 앞의 `부칙 <...>` 제목 줄부터 잘라냅니다. 고정 번호(116)를 쓰지 않아 법 개정에도 대응됩니다.
- **중복 조문 처리**: 현행 조문과 시행 예정 조문이 함께 실린 11개 조항은 먼저 나온 것만 유지합니다.
- **정리**: `<개정 2021. 1. 5.>` 같은 개정 표시를 제거해 LLM에 깔끔한 본문만 전달합니다.

## 보안 설계

### 1. 권한 필터는 AI가 아니라 검색 단계에서
AI에게 모든 문서를 주고 "인사팀 문서는 말하지 마"라고 지시하면, 모델이 실수하거나
프롬프트 조작에 속을 수 있습니다. 대신 **점수 계산 단계에서 권한 없는 조항을 아예 제외해**
AI가 볼 수 없는 정보는 말할 수도 없게 했습니다.

### 2. 부서 정보는 사용자 입력이 아니라 서버가 결정
초기 버전은 화면 드롭다운에서 부서를 고르게 했는데, 이 경우 누구나 "인사팀"을 골라
권한을 우회할 수 있었습니다. 로그인 시 **서버가 DB에서 확인한 부서만 세션에 저장**하고,
질문 처리 시 세션 값만 사용하도록 변경했습니다.

### 3. 비밀번호는 솔트가 포함된 해시로 저장
원문 비밀번호는 저장하지 않습니다. 사용자마다 다른 솔트가 붙어,
같은 비밀번호라도 해시 값이 모두 다릅니다.

### 4. 로그인 실패 메시지 통일
"아이디가 없음"과 "비밀번호 틀림"을 구분하지 않아 계정 존재 여부를 노출하지 않습니다.

### 5. 다층 검증
- 1차: 검색 점수 기준(0.60) 미달 시 LLM 호출 없이 거절
- 2차: 프롬프트로 "참고 문서에 없으면 찾을 수 없다고 답하라" 지시
- 3차: 출력에 한자(중국어)가 섞이면 재생성

### 6. 입력 검증
빈 질문은 서버에서 차단합니다. HTML `required`는 편의용이며, 우회 가능하므로 서버 검증을 기본으로 둡니다.

### 7. 감사 로그
질문마다 시간, 사용자, 부서, 질문, 답변, 근거 문서, 점수를 기록합니다.

```
2026-11-02 17:38:38|kim|임원 보수 언제 나와?|제12조 연차휴가|0.495   ← 영업팀: 임원보수 검색 대상 아님 → 거절
2026-11-02 17:40:25|lee|임원 보수 언제 나와?|제20조 임원보수|0.690   ← 인사팀: 정상 답변
2026-11-02 17:40:41|lee|법카 한도는?|제12조 연차휴가|0.393         ← 규정에 없음 → 추가할 규정 후보
```

## 평가

### 평가셋
30문항 (`eval_set.json`)
- 답이 있는 질문 25개: 근로기준법 22개, 사내 규정 3개
- 거절해야 하는 질문 5개: 권한 없는 문서 1개, 규정에 없는 내용 4개
- 실제 직원 말투를 반영해 법 용어와 다른 표현 위주로 구성 ("야근", "잘리면", "급여명세서" 등)

### 지표
- **Top-3**: 정답 조항이 상위 3개 안에 있고, 1등이 기준값을 넘은 비율
- **거절 정확도**: 거절해야 할 질문의 1등 점수가 기준값 미만인 비율

### 실험 1: 임베딩 검색, 기준값 비교

| 기준값 | Top-1 | Top-3 | 거절 정확도 |
|---|---|---|---|
| 0.50 | 84% | 96% | 20% |
| 0.55 | 76% | 88% | 80% |
| 0.60 | 68% | 80% | 100% |

- 기준을 낮추면 놓침이 줄지만 오답변이 늘어나는 **트레이드오프** 확인
- 정답 조항이 0.526인데 무관한 조항이 0.563인 경우가 있어 **점수 분포가 겹침**
  → 기준값만으로는 둘 다 해결할 수 없음
- 사내 규정 안내에서는 **오답변이 놓침보다 위험**하다고 판단 (직원이 틀린 정보로 행동할 수 있음)
  → 거절 정확도 100%인 0.60 선택

### 실험 2: 하이브리드 검색 (임베딩 + 키워드 보너스)

임베딩은 뜻으로 비교해서 "급여**명세서**" ↔ "임금**명세서**"처럼 핵심 단어가 겹쳐도 특별히 반영하지 않음.
→ 두 글자 단위로 자른 뒤, **드문 조각일수록 큰 가중치(IDF)**를 주는 키워드 점수를 추가.
("근로자", "사용자"처럼 거의 모든 조항에 나오는 단어는 보너스가 거의 없음)

```
최종 점수 = 임베딩 유사도 + W × 키워드 점수
```

| W | 기준값 | Top-3 | 거절 정확도 |
|---|---|---|---|
| 0.0 | 0.60 | 80% | 100% |
| **0.1** | **0.60** | **88%** | **100%** |
| 0.2 | 0.70 | 44% | 100% |
| 0.3 | 0.70 | 60% | 60% |

- 거절 정확도 100%를 유지하는 조합 중 **W=0.1, 기준 0.60**이 가장 높음 → 적용
- W를 키우면 "얼마", "회사" 같은 흔한 조각이 우연히 겹치는 무관한 조항까지 점수가 올라 거절이 무너짐
- 적용 후 "급여명세서 꼭 줘야 해?"가 0.526(거절) → 0.604(정답 제48조)로 개선

### 평가의 한계
- 거절 문항이 5개뿐이라 1문항이 20%에 해당해 수치 변동이 큼
- 기준값을 고른 평가셋과 성능을 잰 평가셋이 같아 **과적합 가능성** 있음
  → 실제 사용 로그로 별도 평가셋을 만들어 재검증 예정

## 트러블슈팅 기록

| 문제 | 원인 | 해결 |
|---|---|---|
| 규정 없이 질문하면 "연차 10일"처럼 틀린 답을 자신 있게 함 | LLM이 학습 데이터 기반으로 그럴듯한 답을 생성 (할루시네이션) | 관련 조항을 프롬프트에 함께 전달 (RAG) |
| 애매한 질문에 답변 중간부터 중국어로 바뀜 | 작은 모델이 불확실할 때 주 학습 언어로 회귀 | 프롬프트 언어 지시, `temperature: 0`, 출력에 한자 감지 시 재생성 |
| "정산 안 하면?" 질문에 "처벌 없음으로 간주"라고 단정 | 규정에 없는 내용을 모델이 추론으로 채움 | 근거 기반 답변 지시 + 점수 기준 검증 |
| 같은 질문인데 실행할 때마다 답이 다름 | 생성 랜덤성 | `temperature: 0` |
| "호텔비" 질문을 키워드 검색으로 못 찾음 | 규정에는 "숙박비"로만 표기 | 임베딩 기반 의미 검색 도입 → "호텔"이 없어도 출장비 조항 0.632로 1위 |
| 규정에 없는 질문에도 무조건 1등 조항을 AI에 전달 | 최고점만 고르고 최소 기준이 없음 | 유사도 기준값 도입 |
| 기준 0.5에서 무관한 조항이 0.505로 통과 | 기준이 무관 질문 점수와 너무 가까움 | 기준 상향 → 이후 평가셋으로 0.60 결정 |
| 실행할 때마다 모든 조항을 다시 임베딩해 느림 | 매 요청마다 문서 임베딩 재계산 | 임베딩을 DB에 미리 저장, 질문만 임베딩 |
| 빈 질문 전송 시 서버 에러 (IndexError) | 빈 문자열 임베딩 결과가 빈 목록 | 서버 측 입력 검증 + HTML `required` |
| 개발용 에러 화면에 코드 경로·실행 콘솔 노출 | Flask `debug=True` | 배포 시 `debug=False` 필수 |
| 함수 안에서 `exit()` 사용 시 서버 전체 종료 위험 | 웹 서버에서 `exit()`는 프로세스를 종료 | `return`으로 변경 |
| 근로기준법 분할 시 부칙의 제1조, 제12조 등이 섞임 | 본문 뒤에 부칙 조항이 이어짐 | 조항 번호가 작아지는 지점을 부칙 시작으로 감지 |
| 마지막 조항에 `부칙 <...>` 제목 줄이 딸려옴 | 부칙 제1조 위치에서 잘라 그 앞 제목 줄이 남음 | 부칙 제1조 위치에서 역방향으로 "부칙"을 찾아 절단 |
| 같은 조항(제60조 등)이 두 번씩 추출됨 | 현행 조문과 시행 예정 조문이 함께 실림 | 같은 제목은 먼저 나온 것만 유지 (어느 버전을 쓸지는 추후 과제) |

## 한계와 다음 계획

### 현재 한계
- 조항 단위 청킹이라 긴 조항 안의 여러 항목이 구분되지 않음
- 정답과 무관 조항의 점수가 겹쳐 기준값만으로 완전히 분리되지 않음 (Top-3 88%)
- MARGIN(0.1)은 아직 평가로 결정하지 않은 값
- 현행/시행 예정 조문 중 어느 버전을 쓸지 정책이 없음
- 권한 때문에 막힌 질문과 규정에 없는 질문이 로그에서 구분되지 않음
- IDF 계산에 권한 없는 문서도 포함됨 (정보 노출 가능성 검토 필요)
- SQLite는 동시 쓰기가 많은 대규모 환경에 부적합
- DB 파일 자체가 유출되면 권한과 무관하게 모든 문서가 노출됨
